DASAR

Apa itu komputasi awan?

Cloud Computing atau komputasi awan adalah komputasi berbasis jaringan yang menggunakan internet untuk menyediakan layanan perangkat keras, perangkat lunak, dan jaringan kepada pengguna.

Infrastruktur yang digunakan berada pada sistem jarak jauh sehingga pengguna tidak harus mengetahui seluruh rincian perangkat yang mendasarinya. Layanan dapat diakses melalui jaringan, sesuai kebutuhan, dan kapasitasnya dapat ditingkatkan atau dikurangi.

01Berbasis internetLayanan diakses melalui jaringan.
02Jarak jauhData atau layanan berada pada infrastruktur remote.
03Sesuai kebutuhanSumber daya dapat digunakan sesuai kebutuhan.

MODEL LAYANAN

Tiga model layanan cloud.

Perbedaannya terletak pada bagian layanan yang disediakan oleh penyedia.

01▣

SaaS

Software as a Service

Layanan perangkat lunak yang disediakan sebagai aplikasi dan dapat langsung digunakan pelanggan melalui internet. Pengguna tidak perlu mengelola instalasi serta pemeliharaan perangkat lunak pada komputernya.

CONTOH:Google Drive dan Google Docs
02⌘

PaaS

Platform as a Service

Layanan yang menyediakan platform, pustaka pemrograman, antarmuka pemrograman, dan metode akses. Pelanggan menggunakan platform tersebut untuk membuat aplikasi.

CONTOH:Google App Engine dan Heroku
03▤

IaaS

Infrastructure as a Service

Layanan yang menyediakan sumber daya komputasi virtual seperti CPU, memori, penyimpanan, dan sumber daya lainnya. Sistem operasi dapat disediakan oleh penyedia atau pelanggan.

CONTOH:Amazon EC2 dan Google Compute Engine.

PERTIMBANGAN PENGGUNAAN

Manfaat dan risiko cloud.

Layanan cloud memberi kemudahan, tetapi tetap memiliki hal-hal yang perlu diperhatikan.

＋

Manfaat

  • Penghematan biaya: tidak selalu perlu membeli perangkat keras dan perangkat lunak sendiri.
  • Akses dari mana saja: data dan layanan dapat diakses melalui internet.
  • Pembaruan perangkat lunak: aplikasi berbasis web dapat memperoleh pembaruan secara otomatis.
  • Kolaborasi lebih mudah: beberapa pengguna dapat bekerja pada dokumen atau proyek bersama.
  • Fleksibilitas: sumber daya dapat disesuaikan dengan kebutuhan.
!

Risiko dan kelemahan

  • Bergantung pada internet: layanan sulit atau tidak dapat diakses ketika koneksi terputus.
  • Keamanan data: data yang disimpan di cloud dapat menghadapi risiko akses tidak sah.
  • Kehilangan data: data yang tersimpan dapat hilang dan pengguna mungkin tidak memiliki salinan lokal.
  • Ketergantungan penyedia: penggunaan layanan pihak lain dapat membatasi fleksibilitas.
  • Gangguan layanan: server yang bermasalah dapat menghambat akses.

PERTANYAAN PEMAHAMAN

Memahami proses deployment.

01

Apa perbedaan fungsi Google Drive sebagai SaaS dengan GitHub Pages sebagai layanan untuk mempublikasikan website?

Google Drive merupakan contoh layanan online drive yang termasuk SaaS, yaitu aplikasi yang dapat langsung digunakan melalui internet. Pengguna memanfaatkannya untuk menyimpan dan mengelola berkas secara online. Sementara itu, GitHub Pages pada tugas ini digunakan untuk mempublikasikan berkas website statis agar dapat dibuka melalui URL publik. Jadi, fungsi utamanya berbeda: Google Drive menyediakan aplikasi penyimpanan berkas, sedangkan GitHub Pages menerbitkan website.

02

Apa yang dimaksud dengan deployment dan URL publik pada tugas ini?

Deployment adalah proses mengunggah dan menerapkan berkas website ke layanan hosting agar website dapat diakses melalui internet. Dalam tugas ini, website dipublikasikan menggunakan GitHub Pages. URL publik adalah alamat website yang dapat dibuka oleh orang lain melalui browser. Dengan alamat tersebut, dosen dapat melihat website tanpa harus membuka file langsung dari laptop pembuatnya.

03

Setelah website dipublikasikan, di manakah berkas website tersimpan dan dijalankan?

Berkas sumber website disimpan di repositori GitHub yang dibuat untuk tugas ini. GitHub Pages menggunakan berkas tersebut untuk menerbitkan website melalui layanan hosting. Ketika pengunjung membuka URL publik, halaman website dikirim melalui internet dan ditampilkan oleh browser pengunjung. Karena itu, website tidak dijalankan dari folder lokal laptop pembuatnya.

04

Mengapa website tetap dapat diakses ketika laptop mahasiswa dimatikan?

Website tetap dapat diakses karena berkasnya sudah dipublikasikan pada layanan hosting GitHub Pages. Layanan tersebut berjalan pada infrastruktur penyedia, bukan bergantung pada laptop mahasiswa yang membuat website. Selama layanan hosting dan koneksi internet pengunjung tersedia, website dapat dibuka melalui URL publik. Laptop mahasiswa hanya diperlukan saat membuat atau memperbarui berkas website.

05

Apa yang terjadi ketika perubahan versi 2 diunggah dan dipublikasikan ulang?

Perubahan pada website disimpan dan diunggah kembali ke repositori GitHub melalui commit. Setelah itu, GitHub Pages melakukan deployment ulang menggunakan berkas yang telah diperbarui. Perubahan tersebut akan tampil pada website yang dipublikasikan. URL publiknya tetap sama, tetapi isi atau tampilannya sudah menunjukkan versi 2.

06

Risiko privasi apa yang dapat muncul pada repositori dan website publik, serta bagaimana cara menguranginya?

Repositori dan website publik dapat dilihat oleh orang lain, sehingga informasi pribadi yang dimasukkan berisiko diketahui pihak yang tidak berkepentingan. Kata sandi, API key, dan data pribadi sensitif tidak boleh dimasukkan ke dalam berkas website maupun repositori. Risiko dapat dikurangi dengan hanya menampilkan informasi yang aman untuk dipublikasikan dan memeriksa kembali seluruh berkas sebelum diunggah. Tautan tugas juga perlu diperiksa agar hanya informasi yang memang ingin dibagikan yang dapat diakses.
